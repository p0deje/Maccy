## 理由

Phase-1 对 61 份审计文档逐条做出的判定中,所有 `action` 取值为以下三者之一,**无 `"delete"`**:

- `keep` — 当前权威或冻结原始档案,正文不动。
- `keep-banner` — 历史/冻结文档,顶部加 banner 指向权威源;正文保留作审计痕迹。
- `rewrite` — 仅最小化修正少数被推翻的高信号断言(00-executive-summary、14-master-plan、15-progress-and-resume)。

判定依据(为何一律保留而非删除):

1. **冻结的根因图谱有价值** — 06-14 深度审计(00-08、09、99)与路线图 spec(README/A/B/C/step-*)是后续每一步被测量完成度所依据的 spec-of-record;其 finding-id 词汇(load-no-pipeline-offload、07-F-010、LT-CPP-03 等)被全仓引用。
2. **历史快照有审计痕迹价值** — BS-2 崩溃复盘的 SwiftData 双表示法教训、06-21/06-22 渲染风暴根因、06-23 死代码清扫(其 Tier-1 已被 3 个清理提交采纳)均为不可重建的过程证据。
3. **被推翻 ≠ 无用** — 06-24(213MB 图为中心画像)、06-25 套件的内存目标断言虽被 06-27/06-28 推翻,但保留了"为什么曾这样认为"的推理链;banner 已明确标记其状态,读者不会被误导。
4. **原始捕获数据永不删除** — `docs/maccy.*.txt` 与 06-27 `captures/` 是 06-27 内存权威结论的源数据。
